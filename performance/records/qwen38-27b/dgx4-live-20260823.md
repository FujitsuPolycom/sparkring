# Qwen3.8-27B EXL3 K5/K6 four-Spark live bring-up

Lane: **public-functional**. Status: **research-only**. Hardware: four NVIDIA
DGX Sparks in the direct-cable cycle at TP4/DCP1. Evidence scope: one bounded
startup, functional-probe set, and prefill/decode run using a maintainer-held
source-built runtime. The observations are not a qualified performance,
restart, public-reproduction, or production-reliability result.

## Measurement

The decode and scout-prefill run used
`local-inference-lab/llm-inference-bench` commit
`0b4185b5b435e948b199c9077a00b084864aa963`, script version 0.4.29. The
argument-equivalent command below redacts only the site address:

```bash
python3 llm_decode_bench.py \
  --host <rank-0-management-address> --port 8000 --model qwen38 \
  --contexts 4k,16k --concurrency 1,4 \
  --duration 15 --max-tokens 1024 --temperature 0 \
  --prefill-contexts 8k,64k,128k --prefill-metric client \
  --kv-budget 8382750 --display-mode plain --no-hw-monitor \
  --output logs/qwen38-dgx4-quick-20260823.json
```

Duration decode requests used temperature 0, no `top_p`, `ignore_eos=true`,
and OpenAI stream usage. Integrated one-token scouts set `ignore_eos=true` but
omitted temperature and `top_p`; scout-only requests omitted all three. Those
scouts therefore inherited the pinned model defaults, temperature 1.0 and
`top_p=0.95`. Before the matrix, the harness ran one hidden C1 warmup at the
largest requested context for three seconds. Each cell then waited until the
requested running count was stable before opening its 15-second duration
window.

Aggregate decode is OpenAI continuous-usage completion tokens divided by the
client's `time.monotonic` measurement window. All cells reached requested
concurrency with zero request errors, no underfill, no warmup timeout, and no
capacity-limit flag. Streams were intentionally canceled when each duration
window ended; this record makes no finite-request completion or latency claim.
Each duration cell first sent a one-token scout with the same messages to
populate or refresh native prefix state. Its C1/C4 streams therefore measured
deliberately warm repeated-prefix decode, not cold end-to-end request
throughput.

Prefill is one integrated or scout-only request measured as client
`prompt_tokens / TTFT`. Native prefix caching was enabled. The client-metric
run did not preserve a reliable cached-token delta for any scout, so none of
the values is labelled cold or unique-prompt prefill.

The arithmetic, tool, vision, and hybrid-prefix checks were separate bounded
API probes. Their request/response artifacts and the raw 32,480-byte benchmark
JSON remain in a maintainer-held validation workspace because they include site
identities. The public JSON is a sanitized summary, not the raw harness output.
Each coordinate ran once, so no repetition variance or confidence interval is
available.

## Result

### Startup and capacity

The successful start took approximately 328 seconds from rank-0 API process
start to application startup, including one-time target/MTP compilation and
decode graph capture.

| Measurement | Result |
|---|---:|
| Model memory per rank | 5.39 GiB |
| Target compile | 90.09 s |
| Target warmup/profile | 46.10 s |
| MTP compile | 9.11 s |
| MTP warmup/profile | 2.01 s |
| Captured full-decode sizes | 48 |
| Requested/effective attention block | 16 / 1,600 tokens |
| Effective mamba block | 1,600 tokens |
| KV memory per rank | 74.74 GiB |
| Logical KV capacity | 8,382,750 tokens |
| Full-262K maximum concurrency | 31.98x |

NCCL initialized both RoCE devices on every rank and connected four Ring
channels. vLLM selected PYNCCL; no custom SparkRing collective adapter loaded.

### Functional probes

- `/health` and `/v1/models` returned HTTP 200 with model `qwen38` and a
  262,144-token request limit.
- Three fixed-seed, temperature-zero arithmetic requests returned `391` with
  identical reasoning/content hashes.
- The tool parser emitted `multiply` with arguments `{"a":6,"b":7}`.
- A data-URL image request returned the expected marker `VISION_OK`.
- A maintainer-held hybrid-prefix probe passed three bounded checks: greedy
  determinism, an 8,992-token replay with identical output, and distinct
  shared-prefix suffix answers `13` and `17`. Timing is omitted because the
  public record lacks a complete clock and cache-state definition for that
  probe.
- A post-probe server-metric snapshot reported MTP mean acceptance length 3.82
  and 94.1% draft acceptance. These are not whole-window averages.

## Conclusion

The pinned model and maintainer-held runtime implemented TP4/DCP1 serving on
the four-Spark direct cycle for the stated configuration. The bounded probes
show API function across text, tool, image, and hybrid-prefix request shapes,
and the duration cells show that requested C1/C4 occupancy was sustained
without harness error or capacity gates. The observations do not establish a
general performance advantage, complete correctness, or public
reproducibility.

## Limitations

- Every performance coordinate is N=1; no variability or confidence interval
  is available.
- Decode covers only warm repeated-prefix C1/C4 at 4K/16K; it is not cold
  end-to-end request throughput. The 64K/128K cells are single scout TTFT
  observations, not long-context generation tests.
- Native prefix caching was enabled, and no scout has a reliable cached-token
  delta. The prefill values are not cold or unique-prompt measurements.
- No restart, reboot persistence, eager-versus-graph equivalence,
  long-duration serving, LMCache, or SparkCache result was recorded.
- The exact runtime archive, raw benchmark JSON, API responses, and per-rank
  logs are maintainer-held and unavailable in this public artifact.
- The tracked launcher makes pinned scheduler defaults and the requested block
  input explicit, then adds fail-closed identity/process/port checks. The live
  command used the same effective values but did not exercise those wrapper
  checks.

The sanitized machine-readable values are in
[`dgx4-quick-20260823.json`](dgx4-quick-20260823.json).
