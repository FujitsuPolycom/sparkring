# MiMo-V2.6-Flash-RL on four Sparks, 2026-09-22

Status: **implemented, not qualified**. One site, one day, one benchmark
script per configuration. Profile
[`mimo-v26-flash-rl-tp4`](../../../profiles/mimo-v26-flash-rl-tp4/README.md);
runtime contract [image.json](../../../runtime/mimo-v26-flash/image.json).

## Conditions

Four GB10 Sparks in the switchless 0-1-2-3-0 cycle with the managed-mesh
fabric plan applied (routes, neighbor tables, hardware-offloaded EtherType
0x88b5 relay rule on both rails of every rank). Published image
`ghcr.io/fujitsupolycom/sparkring@sha256:26c366af…` (vLLM
`0.26.1rc0+sparkring.native.2160312ffde4`) with the recorded overlay files
bind-mounted; checkpoint files identical to revision `5711b268` except for the
draft configuration's trailing comma, corrected at launch. TP4/DCP1, DiffKV
attention kernel with the PR 839 split-KV verification dispatch, bf16 target
KV and fp8 draft KV, 262,144 configured context, 16 sequences, 8,192-token
batches, 5-token DFlash draft, per-layer linear kernel selection, image 3 /
video 1 / audio 1, custom all-reduce disabled.

Workload as in the [pair record](tp2-pair-20260922.md): 600-token single
stream; eight concurrent 300-token decodes at about 8K context; cold
49,058-token and 122,658-token prefills each followed by a 299-token decode;
1,500-token repetition tests at greedy and temperature 1.0 (longest repeated
8-gram run, 1 means none); one image request. Repeated PyNCCL baselines vary
by about 3 percent single-stream and 5 percent at C8.

Engine-reported KV capacity: 3,284,072 tokens at 30 GiB and
`GPU KV cache size: 2,189,381 tokens` at 20 GiB (8.35 times the configured
context). With both SIRCL sessions the log shows, on every rank, `Spark TP4
graph-only session ready` (control ports 9970/9971, tiered 64K graph kernel)
and `Spark TP4 fused prefill session ready: shape=(8192, 4096) rails=2
exposure=fused`; rank 0 captured 1,152 width-4096 graph nodes. The relay
rule's hardware packet counters on rank 0 grew by tens of thousands of
packets per 30 seconds during the benchmark.

The C8 collapse of the graph-only configuration is an admission effect: a
C8 decode step with a 5-token draft is 48 query rows, above the 32-token
capture ceiling, so those steps ran eagerly and outside the transport's
admitted row shapes. A 64-token ceiling removes it.

## Rejected on this topology

| Configuration | Outcome |
|---|---|
| RoCEnante one-shot all-reduce | Queue-pair connect to non-adjacent ranks times out; clean fallback to NCCL; numbers equal baseline |
| Padded-V symmetric kernel | No gain over DiffKV; 17 percent less KV capacity |
| fp8 target KV (unit or per-token-head scales) | Repeats itself on long outputs |
| Draft length 4 or 7 | 4 within noise of 5; 7 slower |

## Limitations

- Single runs; no confidence bounds. Prefill and decode use one prompt each.
- 120K decode with SIRCL is about 5 percent below the PyNCCL runs.
- The overlay bypasses the image's attestation entrypoint.
- Every follower prints `collective_rpc should not be called on follower
  node` during KV sizing and continues; it is not a failure in this build.
- Video and audio inputs are enabled but only an image request was checked.
