# MiMo B12X attention on four GB10 Sparks

Status: **implemented**, bounded TP4 text checks; not qualified for media,
soak, accuracy or TP2. The [measurement receipt](b12x-tp4-20260923.json)
contains aggregate metrics and SHA-256 identifiers for the retained raw
benchmark files. It does not contain generated text.

## Configuration and comparison

The B12X candidate uses LIL vLLM
`6afb99982576a7a2eb53d667189e859629e22739` and B12X
`4f3028b19c1d8290dc72b6f483aba40de23eae5a`, copied over the SparkRing native
runtime. Native extensions and transport come from image
`c57f939fde8ca5d7134f20ec1da6a16321dd023e662ce2392d94e14390de71a1`, a
child of the published base in [b12x-image.json](../../../runtime/mimo-v26-flash/b12x-image.json)
that contains verification-generated caches. The public builder uses that
published parent directly; that rebuild has not been benchmarked.

The repository builder completed on ARM64 using the published parent and
produced local image
`sha256:3ff98b404ec3ef227438d7f118133c823a1507b440237ecfaa5e123231a32f0c`.
Its syntax and source-label checks passed. The installed MiMo model,
vLLM B12X backend and B12X paged-attention API have identical SHA-256 hashes
to those files in the measured serving image. This is build evidence;
the rebuilt image has not repeated full-model serving tests.

The target checkpoint is `XiaomiMiMo/MiMo-V2.6-Flash-RL`, stored before the
profile's `5711b268169967567844e1e560e8a3966da959b1` metadata correction.
The live launch supplies valid JSON for `dflash/config.json`. The runtime
contract records target config, weight-index and draft-weight identities;
these measurements do not independently rehash every target shard.

Configuration: TP4/DCP1, 262,144 context, 16 admitted sequences, 8,192 batch
tokens, 20 GiB KV per rank, DFlash5, ordinary safetensors, SIRCL graph decode
and fused prefill over the managed mesh. The candidate uses BF16 target and
draft KV and native B12X attention for all 48 target layers and the draft.
V2 is the selected runner. Full and piecewise graphs have a 64-row ceiling.
The engine reports 2,189,381 logical KV tokens; the benchmark's physical
block-count product is not the logical hybrid-cache capacity.

The control uses the earlier source image, V1 runner, a local prepared-B12X
adapter for nine global target layers, Triton for 39 sliding-window layers
and the draft, and FP8 draft KV. It is a composition comparison: multiple
settings and source revisions differ, so it does not isolate one kernel.

## Measurements

`llm-decode-bench` v0.6.2, 20-second decode windows, 1,024 maximum output
tokens, C1/C8 at requested 8K/128K contexts. Prompt prefixes and sampled
outputs vary between runs. Actual token counts are in the receipt. Prefill
comes from the harness's scout request; all recorded cells report zero
errors and no detected loops. Some C8 windows have no completed request;
their throughput is measured from active streams, not completion latency.

| Measurement | Prepared-B12X control | Native B12X, V2 |
|---|---:|---:|
| Prefill, 8K | 4,004 tok/s | 4,005 tok/s |
| Prefill, 128K | 3,246 tok/s | 3,288 tok/s |
| Decode, 8K C1 | 53.10 tok/s | 54.54 tok/s |
| Decode, 128K C1 | 41.25 tok/s | 47.20 tok/s |
| Decode, 8K C8 | 182.15 tok/s | 162.30, 198.97 tok/s |
| Decode, 128K C8 | 160.48 tok/s | 141.82, 148.50 tok/s |
| Normalized steps, 128K C8 | 55.10/s | 56.26, 57.47/s |
| Acceptance length, 128K C8 | 2.91 | 2.52, 2.58 |

At 128K/C8, replacing only the candidate draft attention with Triton produced
140.19 tok/s, 56.35 normalized steps/s and acceptance 2.49. Forcing V1 with
B12X target and draft produced 156.03 and 139.38 tok/s in two runs, with
57.16/57.33 normalized steps/s and acceptance 2.73/2.43. Neither control
demonstrates a consistent recovery of output rate.

Conclusion: native B12X preserves the measured prefill throughput and
supports coherent short text generation. Engine-step throughput improves
modestly in the C8 observations, while differing speculative acceptance
accounts arithmetically for lower output rates. The cause of the acceptance
difference is unresolved. These runs do not establish a general decode win.

## Limits

- The all-B12X configuration has not been launched on TP2; no TP4 throughput
  or capacity figure qualifies the pair profile.
- Image, video and audio limits are configured, but this source composition
  has not repeated those inference checks.
- The fastsafetensors trial produced corrupted text; ordinary safetensors
  is the serving default. The loader failure's mechanism is unresolved.
- Source labels and syntax checks do not establish native-extension ABI
  compatibility for other models or future source revisions.
