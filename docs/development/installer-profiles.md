# Contributing an installer profile

An installer profile is a profile that `sparkring install` sets up end to end on a cabled pair or
four-Spark ring: one pinned checkpoint and its serving settings, on the serving image that all installer
profiles share. The default installer image lock, `runtime/releases/<release>/installer-image.json`
(`installer_image.DEFAULT_LOCK`), pins that image and lists the admitted profiles;
`python -c "from runtime.common.installer_image import DEFAULT_LOCK as L; print(L.parent.name)"` prints
`<release>`. Examples: [`deepseek-v41-flash-tp4`](../../profiles/deepseek-v41-flash-tp4/profile.json)
(four Sparks, guide `install.md`) and the Qwen profiles `qwen38-flash-next-tp2` and
`qwen38-flash-next-qad-tp4` (own guides and a `--checkpoint` table). Users install a profile with:

```bash
curl -fsSL https://raw.githubusercontent.com/FujitsuPolycom/sparkring/one-command-installer/install.sh | bash -s -- --profile <id>
```

## Files in `profiles/<id>/`

| File | Owns | Origin |
|---|---|---|
| `profile.json` | Catalog record (`sparkring-deployment/v1`): status, recommendation, release, guide, evidence scope, launcher | Authored |
| `config.json` | Serving settings (`sparkring-serving-profile/v1`): checkpoint pins, topology, served name, environment, vLLM arguments | Authored |
| `compose/site.example.yaml` | Example Compose site with documentation addresses | Authored: copy an installer profile's file with the same node count; change `name`, `model`, `cache` |
| `SHA256SUMS` | `sha256sum --check` list of the checkpoint's required files | Generated by `scripts/pin_checkpoint.py` |
| `compose/compose.rank<N>.yaml` | Each rank's installer container as a Compose file | Generated by `scripts/generate_compose_examples.py` |
| `README.md` | Optional guide; without it, `guide` is `docs/operations/install.md` | Authored |

Never hand-edit a generated file. Start from `profiles/deepseek-v41-flash-tp4/` (four Sparks)
or `profiles/glm53-flash-nvfp4-spark-tp2/` (two Sparks) and set:

| File | Field | Value |
|---|---|---|
| `profile.json` | `id` | Directory name, ending `-tp2` or `-tp4`; test fixtures take the host count from the suffix |
| `profile.json` | `release` | `runtime/releases/<release>/release.json` |
| `profile.json` | `launcher` | `path` `runtime/common/qwen_flash_next.py`, `actions` `["plan"]`, `fixed_args` `["--profile", "profiles/<id>/config.json"]` |
| `profile.json` | `recommendation` | `recommended`; the generated summary then hides non-recommended rows with the same repository, topology, node count and engine |
| `config.json` | `model` | `repository`, 40-hex `revision`, and `config_sha256` and `index_sha256` from the pin manifest |
| `config.json` | `topology` | `direct-pair-2` or `direct-cycle-4`, matching `--tensor-parallel-size` and `--nnodes` |
| `config.json` | `image_extension` | `toolchain`: the image comes from the lock |
| `config.json` | `served_model_name` | Ends `-TP2` or `-TP4` |
| `config.json` | `cache_namespace` | Model family; names the compile-cache directories (default `qwen-flash-next`) |
| `config.json` | `vllm_args` | `--port` (API port; no test fixes it; existing profiles use 8000, 8015 or 8020) and `--enable-prefix-caching`; no `--kv-transfer-config` |
| `config.json` | `environment` | `SPARKCACHE_ENABLED` `0`; `VLLM_QWEN3_8_*` and `QWEN_*` only for a Qwen3.8-Flash-Next-architecture checkpoint (`installer_image.QWEN4_EXP`) |
| `config.json` | `transport` | Four Sparks only: `peer_hca_maps`, copied from a four-Spark installer profile |
| `config.json` | `smoke` | Optional request settings for the installer's smoke check (`scripts/installer_host.py` `smoke_request`) |

## Registrations outside the profile directory

| Path | Symbol or field | If missing |
|---|---|---|
| `profiles/catalog.json` | `{"id", "path"}` entry | `Unknown profile`; no catalog row, no `SHA256SUMS` |
| `runtime/common/installer_image.py` | `SUPPORTED` (read as `installer.INSTALLABLE`); also `QWEN4_EXP` for a Qwen3.8-Flash-Next-architecture checkpoint | `This profile uses its own guide`, and a lock that lists it fails validation for every profile; outside `QWEN4_EXP`, admission skips the image's Qwen feature and HC-mode checks |
| `runtime/releases/<release>/installer-image.json` | `profiles`, sorted; any edit changes every installer deployment's identity | `<id> is not admitted on image lock …` |
| `runtime/releases/<release>/release.json` | `sha256` of the `installer-image.json` input | No profile of the release loads: `release input changed` |
| `runtime/common/qwen_flash_next.py` | `TOOLCHAIN_CONFIGS` | Rendering refuses: `Select an unchanged canonical serving configuration` |
| `runtime/common/compose.py` | `TOOLCHAIN` (pair) or `TOOLCHAIN_TP4` (ring) | `Compose adapter unsupported`; a ring outside `TOOLCHAIN_TP4` gets no mesh fabric reference |
| `profiles/checkpoints/<owner>--<name>/<revision>.json` | Pin manifest: size, SHA-256, Git blob and LFS identities of every file; generated by `scripts/pin_checkpoint.py` | `No pin manifest …; generate it with scripts/pin_checkpoint.py` |
| `profiles/storage-planning.json` | `checkpoint_allowance_gib["<owner>/<name>"]`: free space reserved for the checkpoint, whole GiB above its size | `No storage allowance for this checkpoint` from `setup.storage_plan` (`sparkring setup storage`; a host that pulls the image under `sparkring up`) |
| `profiles/model-names.json` | `models`, `quant_labels`, `publishers["<owner>"]` | `generate_profiles.py` stops: `needs a standard display name` or `needs a credited publisher` |
| `runtime/common/installer.py`, `scripts/sparkring_installer.py` | Optional: `DEFAULTS` and `--model` choices | `sparkring.py init --model` offers no family default |
| `performance/profile-capacity.json` | Optional: KV capacity record (`tokens`, `source`, `witness`, `conditions`) | The catalog's KV column shows `—` |

Tests that list installer profiles:

- `runtime/common/test_installer_image.py`: `SHARED`. `test_other_models_render_on_the_shared_image` runs for every `SUPPORTED` profile outside `QWEN4_EXP` and forbids Qwen variables; a `QWEN4_EXP` profile needs render assertions of its own.
- `scripts/test_pin_checkpoint.py`: `COMMITTED[(repository, revision)]`.
- `runtime/common/test_installer.py`: the directory count in `test_checkpoint_directory_is_per_cluster_and_revision_and_disjoint`, when no other installer profile pins the revision.
- `runtime/host/test_install_workflow.py`, four Sparks only: the parameters of `test_tp4_command_adopts_the_discovered_mesh_without_network_changes`.
- Row counts in `scripts/test_profile_catalog.py` and model-specific tests, when a `recommended` row hides another.

Hand-maintained pages, which no check compares with the code:

- `docs/operations/install-reference.md`: the profile table in [Serving image and profiles](../operations/install-reference.md#serving-image-and-profiles), the ring list in Four-Spark rings, API ports in Security and host exposure, and checkpoint sizes, allowances and blank-Spark totals in Downloads, storage and outbound hosts.
- In `docs/operations/`: `install.md` (free disk), `images.md` (profile count), `compose.md` (profile list), `compose-files.md` (rank files).
- [`README.md` Profiles](../../README.md#profiles): `--profile` value, API port, checkpoint link and publisher, measured rates or `—`.

## Steps

From the repository root, with `requirements-dev.txt` installed ([testing](testing.md)):

1. Pin the checkpoint: a Hugging Face repository with `config.json` and `model.safetensors.index.json` at a full commit. The script reads the Hub anonymously and downloads no weights:
   `python scripts/pin_checkpoint.py --repository OWNER/NAME --revision COMMIT`
2. Print `config_sha256` and `index_sha256` for `config.json` `model`:
   `python -c "import json,sys;f=json.load(open(sys.argv[1]))['files'];print(f['config.json']['sha256'],f['model.safetensors.index.json']['sha256'])" profiles/checkpoints/OWNER--NAME/COMMIT.json`
3. Write the profile files and every registration above.
4. Put the digest from `sha256sum runtime/releases/<release>/installer-image.json` (LF line endings, per `.gitattributes`) into `release.json`. Change only the lock's `profiles`; a different image needs a distinct release ([releases](releases.md)).
5. `touch profiles/<id>/SHA256SUMS`, then repeat step 1; it also writes that file.
6. Checkpoint GiB and blank-Spark GiB for the pages above, as `required_space` in `runtime/host/checkpoint_plan.py` counts them:
   `python -c "import json,sys;p=json.load(open(sys.argv[1]));s=json.load(open('profiles/storage-planning.json'));r=[f['size'] for n,f in p['files'].items() if n not in p['optional']];G=2**30;print(round(sum(r)/G,1),round((sum(r)+max(r))/G+s['image_allowance_gib']+s['cache_and_jit_allowance_gib'],1))" profiles/checkpoints/OWNER--NAME/COMMIT.json`
7. `python scripts/generate_profiles.py`, then `python scripts/generate_compose_examples.py`. Commit every rewritten file: each Compose deployment label hashes `profiles/catalog.json` and, for installer profiles, the lock.
8. Check; `git add` first, because the last two commands scan tracked files only:
   ```bash
   python scripts/check_repository_layout.py
   python scripts/generate_compose_examples.py --check
   python scripts/profiles.py resolve <id>
   python -m pytest scripts/test_profile_catalog.py scripts/test_pin_checkpoint.py runtime/common/test_installer_image.py runtime/common/test_installer.py runtime/common/test_compose_installer.py runtime/common/test_qwen_flash_next.py runtime/host/test_install_workflow.py -q -rs
   python scripts/check_markdown_links.py .
   python scripts/check_release_safety.py .
   ```
   [CI](../../.github/workflows/ci.yml) is the source of truth and also runs Ruff and the full CPU suite of its `tests` job; no tracked script replicates it locally.

## Invariants the tests enforce

| Invariant | Enforced by |
|---|---|
| Lock list sorted, distinct, within `SUPPORTED`, equal to `SHARED` and `installer.INSTALLABLE` | `runtime/common/test_installer_image.py`: `test_release_lock_lists_every_installer_profile_on_one_image`, `test_shared_lock_profile_list_is_exact` |
| Image, entrypoint and NCCL library come only from the lock; a non-Qwen profile's release names the lock's image | `runtime/common/test_installer_image.py`: `test_release_lock_lists_every_installer_profile_on_one_image`, `test_other_models_render_on_the_shared_image`; `runtime/common/test_compose_installer.py`: `test_installer_profiles_are_compose_profiles_on_the_default_lock` |
| Served model name ends `-TP<nodes>`; `--enable-prefix-caching` set; SparkCache off (`SPARKCACHE_ENABLED=0`, no `--kv-transfer-config`); no Qwen variables outside `QWEN4_EXP`; `XDG_CACHE_HOME` is `/cache/<cache_namespace>-<image>-<revision>`; rank 0 health start period 1800 s | `test_other_models_render_on_the_shared_image` |
| Admission requires the image's Qwen features and HC modes only for `QWEN4_EXP` profiles | `runtime/common/test_installer_image.py`: `test_qwen_admission_features_do_not_apply_to_other_models`, `test_tp2_row_sharding_requires_an_image_that_declares_it` |
| Each rank's Compose export equals the installer container except runtime binding and labels | `runtime/common/test_compose_installer.py`: `test_compose_export_matches_installer_container_for_each_rank`, `test_rendered_service_differs_from_installer_export_only_by_binding_and_labels` |
| Pin manifest and `SHA256SUMS` are generator output; config and index hashes match `config.json`; one checkpoint directory per cluster and revision | `scripts/test_pin_checkpoint.py`: `test_committed_manifests_and_sums_are_generator_output`, `test_every_installer_profile_revision_has_a_committed_manifest`; `runtime/common/test_installer.py`: `test_checkpoint_pins_agree_with_every_installer_profile`, `test_checkpoint_directory_is_per_cluster_and_revision_and_disjoint` |
| A four-Spark profile adopts the running mesh on the default lock | `runtime/host/test_install_workflow.py`: `test_tp4_command_adopts_the_discovered_mesh_without_network_changes` |
| Generated catalog and Compose files equal their generators' output; release inputs match their digests | `scripts/check_repository_layout.py`; `scripts/generate_compose_examples.py --check` |

## Pull request contents

- [ ] The files, registrations and regenerated files above.
- [ ] One `status` in `profile.json` and `config.json`: `research-only` (shown as Experimental) or `implemented` (Development); `qualified` (Validated) follows maintainer release qualification ([releases](releases.md)). Each `implemented` installer profile cites one `sparkring install` run that passed functional checks such as counting, arithmetic and code; without such a run, use `research-only`.
- [ ] `evidence_scope` of the form `<settings> on installer image <release>: <what ran> on <a pair or a four-Spark ring> (<record path>); single-run timing; not serving-qualified.`, limited to what ran; say so when nothing ran on hardware, and name both images when the lock's image differs from the measured one. `config.json` `qualification.scope`: `See the profile evidence scope.`
- [ ] Measurements under `performance/records/images/`, named `<image>-<model>-<topology>-<date>.md` like the existing records, with programs and raw files in the directory of the same name, the five [record sections](../../performance/README.md#evidence-record-format), and no addresses, hostnames or credentials.
- [ ] Validation, per the [PR template](../../.github/PULL_REQUEST_TEMPLATE.md): the CPU checks run and their skips, and any hardware run. CPU tests do not validate CUDA, RDMA, serving or performance; hardware is not required, and maintainers own release qualification. `install.sh --ref BRANCH --repository URL --profile <id>`, with `install.sh` fetched from the same ref, installs a pushed branch ([Get the package](../operations/install-reference.md#get-the-package)).
- [ ] Compatibility: the lock is part of `installer.make_lock`'s digest and of the instance hash in `runtime/host/install_workflow.py`, so editing it gives every installer profile a separate deployment on a later `sparkring install`.
- [ ] Credit: the checkpoint publisher in `profiles/model-names.json` `publishers` and in the `README.md` row. A profile guide opens by naming the checkpoint repository, its publisher and, for a derived checkpoint, the original model and its maker ([example](../../profiles/glm53-flash-spark-tp2-dcp1/README.md)). The repository holds no weights and no checkpoint license ([License](../../README.md#license)); list copied or adapted code and its license in [third-party notices](../../THIRD_PARTY_NOTICES.md).
